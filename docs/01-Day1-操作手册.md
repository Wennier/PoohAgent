## 1. 实现 ① `splitToDeltas`（15 min）

**唯一硬判据**：`splitToDeltas(text).join('') === text`，恒成立。

**步骤**

1. 声明 `const deltas: string[] = []` 和 `let cursor = 0`
2. `while (cursor < text.length)`：
   - 取随机步长 `step`，范围 **1~5**（必须 ≥1，否则死循环）
   - `deltas.push(text.slice(cursor, cursor + step))`
   - `cursor += step`
3. `return deltas`

**边界**

- 空字符串 → 返回 `[]`（不是 `['']`）。因为 `while` 条件天然不成立，正常实现自动满足。
- `slice` 超出末尾会自动截断，不用手写边界判断。
- 允许把中文/emoji 从中间切开——真实场景会这样，正好用来测多字节处理。

**验证方式（按顺序做）**

1. 临时在文件末尾加一行调试输出，跑一次看拼接结果：
   ```ts
   console.log(splitToDeltas('你好abc').join('') === '你好abc');
   ```
2. 确认无误后删掉，改写成正式单测 `test/split-to-deltas.spec.ts`，至少三条用例：
   - 空串 → `[]`
   - 单字符 → 长度为 1 的数组
   - 混合文本 → `join('')` 等于原文
3. 跑测试：`pnpm test`

## 2. 实现 ② `buildScript`（25 min）

**先看事件字段表**（字段名必须完全一致，camelCase）：

| 事件 | 必带字段 |
|---|---|
| `RUN_STARTED` | `type`、`timestamp`、`threadId` |
| `TEXT_MESSAGE_START` | 上面 + `messageId`、`role: 'assistant'` |
| `TEXT_MESSAGE_CONTENT` | 上面 + `messageId`、`delta` |
| `TEXT_MESSAGE_END` | 上面 + `messageId` |
| `RUN_FINISHED` | `type`、`timestamp`、`threadId` |

**步骤**

1. `const messageId = \`msg_${Date.now()}_assistant\``
2. `events` 先放 `RUN_STARTED`、`TEXT_MESSAGE_START`
3. `for (const delta of splitToDeltas(MOCK_REPLY))` 推入 `TEXT_MESSAGE_CONTENT`
4. 推入 `TEXT_MESSAGE_END`、`RUN_FINISHED`，然后 `return events`

**三个必须一致的地方**（错了极难查）

- 所有事件的 `threadId` 必须等于入参 `threadId`
- 所有 `CONTENT` 的 `messageId` 必须等于 `START` 的 `messageId`（客户端靠它定位"追加到哪条消息"）
- 事件顺序必须严格是 START → CONTENT×N → END

**验证方式**

写 `test/build-script.spec.ts`，断言：

- `events[0].type === 'RUN_STARTED'`
- `events.at(-1)?.type === 'RUN_FINISHED'`
- 把 `type` 映射成数组后，等于 `['RUN_STARTED','TEXT_MESSAGE_START', ...cont, 'TEXT_MESSAGE_END','RUN_FINISHED']`
- 所有事件 `threadId` 相同
- `CONTENT` 的 delta 拼起来等于 `MOCK_REPLY`

纯函数，不需要起 server 就能测——这是它被设计成纯函数的意义。

## 3. 实现 ③ `writeEvent`（10 min）

**帧格式**（一个字节都不能少）：

```
data: <JSON>
<空行>
```

对应字符串就是 `` `data: ${JSON.stringify(event)}\n\n` ``。

**步骤**

1. `const frame = \`data: ${JSON.stringify(event)}\n\n\``
2. `res.write(frame)`
3. `console.log(\`[mock] → ${event.type}\`)`

**三个常见错误**

| 错误 | 后果 |
|---|---|
| 只写一个 `\n` | 客户端把下一帧当成同一帧的续行，事件全乱 |
| `JSON.stringify(event, null, 2)` | 多行 JSON，解析器要额外处理多行 `data:`，平白增加复杂度 |
| 没有空行 | 客户端一直等，直到连接结束才收到 | 

**验证**：进度到第 4 步统一验，这一步单独跑没意义。

## 4. curl 验收 mock（15 min）

重启服务，重复 §0.3 的 curl 命令。期望：**一行行陆续到达，总耗时约 2 秒**，末尾是 `RUN_FINISHED`。

完整输出形如：

```
data: {"type":"RUN_STARTED","timestamp":1793013361037,"threadId":"thread_1793013361036"}

data: {"type":"TEXT_MESSAGE_START","timestamp":...,"threadId":"thread_...","messageId":"msg_...","role":"assistant"}

data: {"type":"TEXT_MESSAGE_CONTENT","timestamp":...,"threadId":"...","messageId":"msg_...","delta":"你好，我是"}

...（约 60~70 条）

data: {"type":"TEXT_MESSAGE_END",...}

data: {"type":"RUN_FINISHED",...}
```

**判定表：现象 → 原因**

| 现象 | 最可能的原因 |
|---|---|
| `bytes=0` 且服务端 `done (0 events)` | `buildScript` 还是 `return []` |
| 服务端有 `→ RUN_STARTED` 但 curl 无输出 | `writeEvent` 没真正 `res.write` |
| 一次性全部刷出，没有"逐行到达" | 循环里没有 `await delay(...)`，或没 `flushHeaders()` |
| 末尾没有 `RUN_FINISHED` | `events` 数组顺序或拼装漏了 |
| curl 一直挂着不结束 | 忘了 `res.end()` |
| `405` | 用了 GET |
| `404` | 路径不是 `/api/v6/agentgateway/chat` |
| 中文乱码 | 你改了 §4 的 `readBody`（原实现用 Buffer 拼接，不会乱码） |
| `http=200` 但内容里 `threadId` 为空 | `resolveThreadId` 被改坏了 |

✅ 通过标准：逐行到达、约 2 秒结束、序列完整、`threadId` 有值。

判据：`pnpm typecheck` 通过。

### 5.2 `sse-parser.ts`（35 min）—— 今天的核心

**做什么**：`ReadableStream<Uint8Array>` → 一帧一帧的字符串。

**实现要点**

1. `const reader = stream.getReader()`
2. `const decoder = new TextDecoder('utf-8')`
3. 维护一个字符串缓冲区 `buffer`
4. 循环 `const { done, value } = await reader.read()`
   - `done` 为 true → 退出循环
   - `buffer += decoder.decode(value, { stream: true })` ← **`stream: true` 必须有**
5. 在 buffer 里找帧分隔符，找到一个就 `yield` 一帧并把它从 buffer 里切掉
6. 注意：一帧可能跨 chunk（buffer 里没有完整帧时继续读），也可能一个 chunk 有多帧（while 循环切干净）

**帧分隔符的坑**：HTTP 规范允许 `\r\n\r\n` 与 `\n\n` 两种，真实环境可能混用。**两种都要兼容**。

**多行 data 的坑**：一帧里可能有多条 `data:` 行（多行 payload），按规范要用 `\n` 连接，不是直接拼接。

**验证方式**（这一步值得写单测）

自己造一个假的 `ReadableStream`，把同一段文本按不同切法喂进去，断言输出帧序列完全一致：

- 一次性喂完
- 每 1 字节喂一次
- 切在 `data:` 中间
- 一次喂两帧（粘包）
- 混入 `\r\n`

五种切法结果必须一样。**这条测试过了，你的解析器基本就不会错。**
