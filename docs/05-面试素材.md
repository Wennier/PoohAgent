## 一、Day 2 三条（内容见 03 §三）

### 1. `finish` 混了两种生命周期 → 中止静默失效

**30 秒稿**

> 我的收尾函数把「这一轮回答结束」和「连接结束」合成了一件事。结果 `RUN_ERROR` 一到就释放了中止句柄，但流其实还开着——用户点中止静默失效，请求继续跑完。
>
> 这是建模错误：run 的生命周期 ≠ 连接的生命周期。拆成 `settleRun()` 和 `releaseConnection()` 后解决，收尾做成幂等 + 身份比较。

**追问**

- *单测为什么没抓到？* → 假连接是"事件 + complete"一起给的，不存在"错误已到但连接仍开着"的中间态。79 条全绿时 bug 仍在，是真实链路实测抓到的（文本从 38 字涨到 168 字）。
- *身份比较解决什么？* → 上一轮 error 回调迟到时，不会把新一轮的 controller 清掉。
- *口径*：这条的重点不是"我会写幂等"，而是"我知道单测构造不出这个中间态"。

### 2. 归约的"规范形式"：两条路径凭什么等价　**未解决**

**30 秒稿**

> 同一会话有两条数据入口：增量事件、完整历史。两份实现必须收敛到同一个 UI 模型，否则刷新一次就会露馅。
>
> 真正难的不是写两个函数，而是**定义"等价"**。我最初以为等价 = 文本一样，后来发现协议里既没有 `run_id` 也没有 `parentMessageId`——"哪几条属于同一轮"只能靠顺序启发式猜。所以等价性从"结构等价"退化成"在给定猜测规则下收敛"。

**追问**

- *为什么不复用增量逻辑重放历史？* → 增量假设"有 START、顺序正确、delta 不重复"，历史三条全不满足。
- *等价怎么验证的？* → 一条测试：事件重放与扁平折叠产出的 `parts` 数组 `deepEqual`。这是工程约束下的验证，不是形式化证明——要主动说"不是证明"。
- *口径*：主动说"这一步我没做到位"，比被问出来好。

### 3. 逐帧不可变更新的代价　**未解决，只定位**

**30 秒稿**

> 流式时每收一个 delta 就产出新数组、新消息、新 parts，一轮 60 帧就是 60 次全量复制加最多 60 次重渲染。我**没做优化**，但能讲清代价和解法分层：结构共享、按消息粒度订阅、rAF 合帧——最后一层的代价是**增加端到端延迟**，逐字感会变成一跳一跳。
>
> 真正的取舍是"端到端延迟 vs 每秒渲染次数"，要选一个 frame budget。

**口径**

讲"我知道代价在哪、什么时候付账"，**不讲"我优化了"**。

## 二、Day 3（内容见 04 §三）

### 4. 缺"产品对象 + 边界规则"时，加一种 part 会变成改地基

**30 秒稿**

> 纯文本跑通后，第三天只是加一种消息片段（工具卡），工作量看着很小，但我做得非常吃力。定位下来不是少写一个组件，而是三个从没定义过的东西：`Part` 只有类型清单、没有产品语义；`UIMessage` 的**边界规则**从没定义；`messageId` 一词多义（消息 / 文本段）。
>
> 核心判断是：**一条 UI 消息的边界由"一次 run"决定，不是由协议里的文本片段决定**。协议会把一次回答切成多段（工具前后各一段），但用户认知里它是一次回答。

**追问**

- *怎么落地的？* → 引入"本轮正在写的消息"指针（`LiveContext`），两处重置：`RUN_STARTED` 与 `submit()` 开头——后者是因为 `RUN_ERROR` 不清指针，异常结束后不重置会把新一轮写进上一轮。
- *如果重来？* → 先画"一条回答长什么样"再定类型；第二天就定义消息边界并覆盖"两个 `TEXT_MESSAGE_START`"；四个 id 从第一天分开。
- *口径*：这条讲的是**设计认知的补课**，不是功能实现。

## 三、Day 1（内容见深挖卡）

### 5. 手写 SSE：分层的依据是"出错单位"

**30 秒稿**

> `EventSource` 只能 GET、不能带 body、不能自定义 header、只能 `close()`——而我们要 POST 历史、带 XSRF、区分"用户取消"和"网络断开"。所以 `fetch` + `ReadableStream` 自己解析，拆三层：字节→字符、字符→帧、帧→事件。
>
> 分层依据不是"职责清晰"，而是**每层的出错单位不同**——出问题能立刻定位到层。最难是帧边界：一帧可能跨 chunk、一个 chunk 也可能多帧、缓冲区一个字节不能丢。

**追问**

- *怎么验证帧解析？* → "五种切法"单测：一次性喂完 / 每字节一次 / 切在 `data:` 中间 / 一次两帧 / 混 `\r\n`，结果必须一致。
- *坏帧为什么返回 null 而不抛错？* → 流式场景"部分可用"优于"全有全无"；代价是错误被静默吞掉，所以补了 warn + 计数。
